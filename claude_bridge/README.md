# Claude Telegram Bridge — Claude Code у тебя в Telegram

Мост, который превращает Telegram-бота в удалённый пульт к Claude Code.
Схема:

```
Телефон (Telegram) → бот @...  → bridge.py на твоей машине → claude -p → ответ обратно в Telegram
```

- Работает на любой машине, которая включена 24/7: сервер, десктоп, ноутбук.
- Публичный IP / проброс портов НЕ нужны — long polling, как у бота парсера.
- Контекст диалога сохраняется (`claude --resume`): можно вести беседу,
  уточнять, продолжать задачу.
- Только stdlib Python 3.9+ — ничего ставить по pip не нужно.

## Что нужно заранее

1. **Claude Code CLI** установлен и авторизован на машине, где будет жить мост:
   ```bash
   npm install -g @anthropic-ai/claude-code
   claude          # войти в аккаунт (один раз, интерактивно)
   ```
   Для сервера без браузера удобнее долгоживущий токен: `claude setup-token`
   (выполнить на машине с браузером, значение положить в env
   `CLAUDE_CODE_OAUTH_TOKEN` сервиса), либо `ANTHROPIC_API_KEY`.

2. **Новый Telegram-бот** — НЕ переиспользуй бота парсера (два long-poll
   процесса на одном токене конфликтуют):
   - `@BotFather` → `/newbot` → имя, например «Claude Помощник» → получишь токен.
   - Узнай свой user ID: напиши `@userinfobot`, он ответит числом.

## Установка (Linux-сервер, например 212.116.115.150)

```bash
cd /home/hvac_parser && git pull        # или git clone репозитория
cd claude_bridge
cp .env.example .env
nano .env        # BRIDGE_BOT_TOKEN, BRIDGE_ALLOWED_USER_IDS, CLAUDE_BIN

# проверка руками:
python3 bridge.py
# написать боту "привет" — должен ответить Claude. Ctrl+C.

# автозапуск:
sudo cp claude_bridge.service /etc/systemd/system/
# в юните проверить User=, пути WorkingDirectory/ExecStart и PATH
sudo systemctl daemon-reload
sudo systemctl enable --now claude_bridge.service
journalctl -u claude_bridge -f
```

## Установка (Windows-десктоп/ноутбук)

1. Установи Python 3 и Claude Code, авторизуйся (`claude` в терминале).
2. Скопируй папку `claude_bridge`, создай `.env` из `.env.example`.
3. Проверка: `python bridge.py` в терминале, напиши боту.
4. Автозапуск: Планировщик заданий (Task Scheduler) → «Создать задачу» →
   триггер «При входе в систему» → действие
   `pythonw.exe C:\путь\claude_bridge\bridge.py`,
   «Рабочая папка» = папка моста. Галка «Перезапускать при сбое».

## Использование

Просто пиши боту задачи текстом:

> «посмотри логи парсера за сегодня и скажи, были ли ошибки»
> «добавь в vk_groups фильтр по слову X, закоммить и запушь»

Команды:

| Команда | Что делает |
|---|---|
| `/new` | новый диалог, сброс контекста |
| `/project <имя или /путь>` | сменить рабочую директорию (проект) |
| `/projects` | список проектов из `BRIDGE_PROJECTS` |
| `/status` | текущий проект, сессия, активна ли задача |
| `/stop` | прервать выполняемую задачу |
| `/help` | справка |

Пока Claude работает, бот показывает «печатает…». Новые сообщения во время
работы встают в очередь. В конце ответа — время, число шагов и стоимость.

## Безопасность — прочитай обязательно

- Кто может писать боту — тот **выполняет код на твоей машине**. Поэтому
  `BRIDGE_ALLOWED_USER_IDS` обязателен: чужим бот отвечает «Доступ запрещён»
  и ничего не делает.
- Токен бота — секрет. Только в `.env` (gitignored), не в коммиты.
- `BRIDGE_PERMISSION_MODE=acceptEdits` (дефолт) разрешает Claude править файлы;
  `bypassPermissions` — полная автономия (Claude может выполнять любые команды
  без подтверждения). Включай bypass только если понимаешь риск.

## Траблшутинг

- **Бот молчит** → `journalctl -u claude_bridge -n 50`. Частое: не найден
  `claude` (пропиши абсолютный путь в `CLAUDE_BIN`), либо не авторизован
  (`claude` под тем же пользователем, что в юните).
- **409 Conflict в логах** → два процесса моста на одном токене. Оставь один.
- **Ответ «Credit balance is too low» / ошибка авторизации** → перелогинься в
  Claude Code на этой машине.
- **Задача длинная и оборвалась** → подними `BRIDGE_TASK_TIMEOUT`.
